# TP-RAG 會後調整版 UI

本資料夾供客戶確認畫面與操作流程。原版保留於 `../原版UI/`，後續調整只修改本資料夾。直接開啟 `index.html`，展開「知識庫與檔案匯入管理」即可查看。

## 已確認需求（2026-10-29）

- 現階段不需要會員管理；每次問卷紀錄保存訪客名與 Email，不要求建立會員。
- 知識庫資料由上傳建立，後續可在後台維護內容。
- 各資料類型的區塊及欄位結構固定，資料列與明細項目可新增。不得把「新增元素／規則」誤解成「自由新增系統欄位」。
- 營養模板的適用對象、常見犬種、備註與計量基準為固定區塊，內容可修改。
- 營養元素採共用主檔，各模板引用元素並分別設定數值。新增元素可供所有模板選用，不必每次改程式或資料庫欄位。
- 換算公式不納入本次資料維護頁。流程說明不作為資料維護類別。
- 資料分類依 `參考資料/0803營養標準模板_狗_假資料.xlsx` 的實際工作表整理，不混入其他來源或參考 UI。

## 本版畫面與操作

- 知識庫選單可展開／收合，包含資料維護、檔案匯入紀錄、異動明細。
- 資料維護共用類型切換、搜尋、狀態及編輯視窗；各類使用自己的欄位。
- 共 11 個類型選項：營養標準模板、營養元素、MER 係數、犬生命階段判斷表、活動量加成、BCS 加成、過敏原清單、慢性病與遺傳性疾病營養、排便分類法、飲水量清單、亞健康觀察清單。
- 9 個營養標準模板合併為同一個管理入口，透過模板選擇切換。元素主檔由來源的中文名、英文名、單位整理為 42 項；這是匯入快照的初始整理，非客戶正式核定的元素字典。
- 模板可新增、修改基本資料、加入既有啟用元素、修改獨立標準值。空白值與零分開保存。
- 元素可新增、編輯名稱及別名、停用；已被引用的元素鎖定單位。停用保留既有引用，但不可再新增引用。不提供刪除以免中斷引用。
- 其他類型支援新增、檢視／編輯與停用；複雜資料保留來源規則屬性及明細列，可新增明細。這是來源保真呈現，正式業務表單及欄位驗證仍待工程規格細化。
- 編輯視窗支援取消、未儲存離開確認；異動明細記錄修改前後值、時間及示範操作者。
- 元素重名檢查、模板重名檢查、重複識別值檢查與非負模板數值檢查僅為本機示範層級。模板值保留來源的 ND、比例與範圍，不強制轉為數字；正式數值型別及驗證規則仍需定義。

## 元素與匯入對應設計

1. 元素採穩定識別碼；名稱可以修改，既有模板使用識別碼引用。
2. 正式匯入優先使用元素代碼，其次比對中英文名稱與已確認別名。不得自行模糊合併。
3. 無法唯一對應的項目，需要人工選擇既有元素或建立新元素。
4. 名稱相同而單位不同不得直接覆蓋；單位換算需另外定義。
5. 模板匯入預設只更新指定模板的引用與數值，不順便改寫共用元素主檔。
6. 此版「使用來源檔案預覽」使用已載入的原始 Excel 元素快照，展示對應確認及紀錄。未實作新檔案讀取、正式批次更新或覆寫模板。新增元素需先到主檔建立，再重新預覽。

## 原型界線

來源是客戶假資料，未經營養標準審核。`knowledge-data.js` 是從原 Excel 產生的固定快照。操作以獨立的 `tp-rag-meeting-knowledge-v1` localStorage 保存，不影響原版的知識庫儲存鍵。

尚未提供正式後端、真實操作者身分、檔案上傳、跨裝置同步、完整匯入交易、RAG 更新、營養計算連動、版本退回。示範的資料維護不會回寫原始 Excel，也不會改寫既有推薦紀錄。

## 內部開發備註：流程缺口與建議（不呈現於客戶 UI）

以下為工程規格準備事項，不代表客戶已核定：
1. 新資料不顯示既有資料比對畫面，但後端仍應檢查檔案內重複、識別碼／名稱已存在及格式錯誤。遇到錯誤顯示位置、欄位及修正方式，不靜默合併。
2. 更新以穩定識別碼定位，名稱及別名僅協助首次對應。檔案未包含的舊項目預設保留；刪除或整批取代須另訂明確行為。
3. 未知營養元素在匯入流程內完成建立或對應；共用元素需涵蓋模板、疾病、排便、亞健康，不只模板。單位及可疑拼字不能自動推斷合併。
4. 初期建議整批驗證成功才寫入；任一錯誤則不寫入，避免半成功。提交時重新驗證並以交易保護資料、引用及紀錄的一致性。
5. 儲存是否立即生效、是否需審核發布、計算／索引如何同步需確認。歷史推薦保留當次快照，規則衝突優先順序不能自行相乘。
6. 同時編輯需檢查資料修訂碼，避免後儲存覆蓋他人修改。完整版本還原及匯入批次復原另議，目前僅異動明細。
7. 工程規格應將正式權限、操作者身分、保存期間及不可竄改要求補齊，localStorage 原型不提供這些保證。

## 異動明細呈現與修正入口

客戶 UI 不顯示整包 JSON，僅列有差異的欄位：時間、操作者、動作／資料、欄位中文名稱及 key 路徑、修改前值、修改後值、前往修改。模板元素以 elementId 比較，避免順序改變被誤判為數值變更；資料陣列優先按 id 比較。新增／移除只列受影響欄位。空白、未提供、不存在、零與布林值分開顯示。

新紀錄保存類型、模板／資料識別碼及欄位資訊供定位。前往修改開啟目前值，模板於原頁編輯並聚焦欄位，元素與其他資料開啟既有編輯視窗。修正由使用者確認儲存，不自動還原歷史值。無變更儲存不產生可見差異列。無法辨識來源的舊紀錄不提供錯誤跳轉。

工程建議：後端按欄位保存 typed before/after、穩定欄位 key、記錄 ID 及來源批次，不必依賴 UI 比較整份快照。延伸明細目前以列號定位，正式設計應補獨立明細 ID，避免新增／排序影響識別。欄位刪除或資料已不存在時，應提示並保留稽核紀錄。


異動明細空白狀態：若本機沒有可顯示的真實欄位差異，提供三類明確標示的示範紀錄供客戶確認版面；示範不寫入 localStorage、不冒充真實異動。產生實際異動後改顯示真實紀錄。匯入結果示範本身不會產生真實異動，因此不能期待匯入示範後有真實歷史。若舊紀錄前後相同或缺少資訊，不得捏造還原。


異動明細最新排版：一次修改一列，取消獨立欄位／Key 欄。當次所有變更欄位，以相同順序分別列在修改前、修改後兩格；每個項目包含中文欄位、key 與值。操作入口每次修改只顯示一次，進入目前資料編輯。


異動明細改為預設收合：主列顯示時間／操作者、動作／資料、異動欄位數與摘要及操作；按展開明細才顯示同次修改的前後 key/value 對照。每筆獨立展開或收合，前往修改保持可直接使用。


異動明細移除上方示範提示橫幅；示範性質仍在各列標示。展開控制改為每列最左側的 SVG 線條箭頭，收合向右、展開向下，無多餘外框；右側僅保留前往修改，區分檢視與編輯操作。
